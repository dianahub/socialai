# Restaurant Social AI — Claude Code Project

## What this project does
Automated social media content generation for fine dining restaurants.
Takes restaurant assets (logo, food photos, owner photo) and produces:
1. Food photo slideshow video (ffmpeg, Ken Burns + crossfade) — no avatar, no face
2. Owner Twin video — owner photo animated via HeyGen Talking Photo (9:16, owner speaks to camera)
3. Branded image posts for Instagram / Facebook / TikTok (Sharp, 1080×1080 feed + 1080×1920 story)
4. Weekly scheduling UI — "Generate This Week" creates a full week of posts and queues generation jobs

## Stack
- Frontend: Single-file HTML/JS served by Express (`public/`)
- Backend: Node.js + Express (`server.js`, `routes/`)
- Video generation: ffmpeg via `@ffmpeg-installer/ffmpeg` + `fluent-ffmpeg` (slideshow); HeyGen API (owner twin)
- Image processing: Sharp (brand overlay, resize, logo badge)
- Asset storage: Cloudinary (persistent across server restarts)
- Database: SQLite via Prisma 7 + libsql driver adapter (`data/restaurant.db`)
- Queue: `lib/jobQueue.js` — polls DB every 10s for pending GenerationJob records
- Cron: `node-cron` — hourly check for auto-generate day/hour match

## Database — Prisma + SQLite
Schema: `prisma/schema.prisma` — 6 tables: Restaurant, FoodPhoto, ScriptTemplate, ScheduledPost, GenerationJob, WeeklyBrief.
Migrations: `prisma/migrations/` — run `npm run db:migrate` on first deploy.
Seed: `npm run db:seed` — inserts demo restaurant "Osteria della Luna".
Client: `lib/db.js` — Prisma singleton using `@prisma/adapter-libsql`.

Restaurant model includes auto-generate fields:
- `autoGenerateEnabled` Boolean @default(false)
- `autoGenerateDay` Int @default(1)  — 1=Monday … 7=Sunday
- `autoGenerateHour` Int @default(8) — hour in 24h

WeeklyBrief model: `restaurantId + weekOf (YYYY-MM-DD Monday)` unique key. Fields: featuredDish, event, promotion, notes.

DB API routes (all under `/api/db/`):
- `GET/POST /api/db/restaurants` + `GET/PATCH/DELETE /api/db/restaurants/:id`
- `GET/POST /api/db/scheduled-posts` + `PATCH/DELETE /api/db/scheduled-posts/:id`
- `GET/POST /api/db/script-templates` + `PATCH/DELETE /api/db/script-templates/:id`
- `GET/POST /api/db/food-photos` + `DELETE /api/db/food-photos/:id`
- `GET/POST /api/db/generation-jobs` + `PATCH /api/db/generation-jobs/:id`
- `GET /api/weekly-brief` + `POST /api/weekly-brief` (upsert by restaurantId + current weekOf)
- `POST /api/generate-week` — creates ScheduledPost + GenerationJob records for a full week
- `GET /api/generate-week/presets` — scheduling preset list
Railway: set `DATABASE_URL=file:/data/restaurant.db` and mount a volume at `/data`.

## Asset storage — Cloudinary
Cloudinary public ID conventions:
- Logo:   `restaurant-social-ai/logo`
- Owner:  `restaurant-social-ai/owner`
- Photos: `restaurant-social-ai/{restaurantId}/photos/photo_{timestamp}_{rand}` (per-restaurant)
- Legacy: `restaurant-social-ai/photos/photo_{timestamp}_{rand}` (shared fallback)

Key files:
- `lib/cloudinary.js` — wrapper: uploadBuffer, deleteAsset, getAssetUrl, listFolder
- `cloudinaryTransformUrl(url, w, h)` in `pipeline/1_generate_content.js` — inserts Cloudinary crop transform (`c_fill,w_,h_,g_center`) so images arrive pre-cropped, skipping Sharp resize

## Generation pipeline

### `pipeline/1_generate_content.js`
- `generateVideo(config, jobId)` — food photo slideshow via ffmpeg
  - Reads `config._photoUrls[]` (up to 6), downloads each, resizes to 1920×1080 with Sharp, stamps logo badge
  - Builds ffmpeg complex filter: `scale+pad` each frame → `xfade=transition=fade` chain → `libx264` mp4
  - Falls back to mock SVG if no photos
- `generateTwinClip(config, jobId, customScript)` — HeyGen Talking Photo (9:16)
  - Downloads owner photo from `config._ownerUrl`, resizes, uploads to HeyGen, polls until done
  - Falls back to mock if no owner photo or no API key
- `generateImagePost(config, jobId)` — Sharp branded images
  - Uses Cloudinary pre-cropped URLs for feed (1080×1080), story (1080×1920), thumbnail (1280×720)
  - Falls back to SVG mock if no photos
- `cloudinaryTransformUrl(url, w, h)` — inserts crop transform into Cloudinary URL

### `pipeline/2_brand_overlay.js`
- Logo badge: bottom-right corner, 14% of image height (increased from 8%)
- Dark background box behind logo, alpha 0.88
- Downloads logo from `config._logoUrl` (cached in `config._logoCached` across variants)

## Queue worker — `lib/jobQueue.js`
Polls `GenerationJob` table every 10s. For each pending job:
1. Fetches restaurant + current week's WeeklyBrief
2. If Cloudinary configured: fetches logo, owner, AND food photos (for video/image job types)
3. Calls the appropriate pipeline function
4. Updates GenerationJob status (completed/failed) + ScheduledPost contentUrl + status

Config built per job includes: `restaurantName, cuisineType, primaryColor, accentColor, ownerName, tagline, _weeklyBrief, _logoUrl, _ownerUrl, _photoUrls`

Job types: `owner_twin_video`, `cinematic_video`, `branded_image_feed`, `branded_image_story`

On startup: `cleanStuckJobs()` resets any jobs left in `processing` state to `failed`.

## Auto-generate cron (`server.js`)
- `cron.schedule('0 * * * *', runAutoGenerate)` — fires every hour
- Checks all restaurants where `autoGenerateEnabled=true` and current day/hour matches
- Calls `kickOffGeneration(restaurantId, config)` which creates meta.json jobs for video, twin, image

## Generate page (`public/generate.html`)
- Three cards: Cinematic Video, Owner Twin, Image Post
- Owner Twin card has embedded script section (always visible):
  - Textarea for reviewing/editing what the owner will say
  - "↻ Generate from brief" button — calls `/api/generate/script`, writes from weekly brief context
  - "Or load saved:" dropdown — only visible if saved ScriptTemplates exist; uses `overflow:visible` on card to prevent dropdown clipping
  - Explicit "Generate Owner Twin" button (card itself has no onclick)
- Stuck job recovery on page load: sets `activejobs.add(i.id)` for any `generating` status items
- Auto-generate toggle + link to schedule page in the weekly brief section

## Schedule page (`public/schedule.html`)
- Week calendar view of ScheduledPost records
- "Generate This Week" modal: frequency, content mix sliders, scheduling preset, start date
- On submit: POST `/api/generate-week` → creates posts + jobs → progress tracking
- Click any post card → detail modal with video player or image preview (uses `post.contentUrl`)

## Key decisions
- Cinematic video uses food photos only — no avatar, no face (user's explicit preference)
- Owner Twin: still photo → HeyGen Talking Photo — only video type that uses a face
- Logo badge size: 14% of image height (user requested bigger)
- gen-card has `overflow:hidden` in CSS — Owner Twin card overrides to `overflow:visible` so template picker dropdown can open
- Weekly brief drives generated scripts: `_weeklyBrief` injected into config for both direct generation and queue worker
- `GET /api/schedule` (mock) kept for backwards compat; real schedule at `/api/db/scheduled-posts`
- Prisma 7: libsql driver adapter — no binary engine; `PrismaLibSql` takes `{ url }` config
